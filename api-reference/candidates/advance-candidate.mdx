## Overview

Advance a candidate to the next stage of the hiring pipeline. The mutation sets `candidateStatus` to `ADVANCED`, records the target stage in `currentStageId`, and emits a `CANDIDATE_ADVANCED` audit event. It is idempotent on the (`candidateId`, `toStageId`) pair — re-running with the same stage is a no-op. Use `rejectCandidate` to move a candidate out of the pipeline instead.

<Note>
This operation requires the **write** scope.
</Note>

## Endpoint

```
POST /graphql
Content-Type: application/json
```

## GraphQL Mutation

```graphql
mutation advanceCandidate($input: AdvanceCandidateInput!) {
  advanceCandidate(input: $input) {
    id
    name
    email
    jobId
    organizationId
    candidateStatus
    currentStageId
    updatedAt
  }
}
```

## Request Parameters

<ParamField body="candidateId" type="string" required>
  UUID of the candidate to advance
</ParamField>

<ParamField body="toStageId" type="string" required>
  Identifier of the pipeline stage the candidate is advanced to
</ParamField>

<ParamField body="reason" type="string">
  Optional reason recorded alongside the audit event
</ParamField>

## Error Responses

| Error Code | Description |
| --- | --- |
| UNAUTHENTICATED | Missing or invalid API key or bearer token |
| FORBIDDEN | The token does not include the write scope |
| BAD_USER_INPUT | `candidateId` is not a valid UUID or `toStageId` is missing |
| NOT_FOUND | The candidate does not exist in the caller's tenant |
| INTERNAL_SERVER_ERROR | Unexpected server-side failure while advancing the candidate |
