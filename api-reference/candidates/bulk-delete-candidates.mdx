## Overview

Soft-delete multiple candidates in one call. Each matched row gets a `deletedAt` marker and disappears from list and report surfaces; the mutation returns the IDs that were actually soft-deleted. IDs that do not exist for the caller's tenant are skipped silently rather than failing the batch, so compare the returned list against your input to detect skips. For a single candidate, use `deleteCandidate` instead.

<Warning>
This operation is irreversible and requires the destructive scope (Admin role). Deleted data cannot be recovered.
</Warning>

## Endpoint

```
POST /graphql
Content-Type: application/json
```

## GraphQL Mutation

```graphql
mutation bulkDeleteCandidates($ids: [UUID!]!) {
  bulkDeleteCandidates(ids: $ids)
}
```

## Request Parameters

<ParamField body="ids" type="array" required>
  Array of candidate UUIDs to soft-delete. IDs that do not exist in the caller's tenant are skipped silently and omitted from the returned list.
</ParamField>

## Error Responses

| Error Code | Description |
|------------|-------------|
| UNAUTHENTICATED | Missing or invalid authentication credentials |
| FORBIDDEN | The caller lacks the destructive scope (Admin role) required for delete operations |
| BAD_USER_INPUT | The `ids` variable is missing or contains a value that is not a valid UUID |
| INTERNAL_SERVER_ERROR | Unexpected server error while performing the deletes |
