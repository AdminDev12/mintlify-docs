## Overview

Poll the status of an asynchronous bulk resume-upload job. The `POST /candidates/bulk-upload-resumes` HTTP endpoint returns `{ jobId }` immediately; call this query with that ID until `status` reaches `COMPLETED` or `FAILED`, then refetch the job's candidates (for example with `candidatesByJob`). The query returns `null` if the job does not exist for your tenant.

<Info>
  Exterview has no customer-facing outbound webhooks. Integrators poll this operation until the result is available.
</Info>

## Endpoint

```
POST /graphql
Content-Type: application/json
```

## GraphQL Query

```graphql
query GetBulkUploadJob($id: UUID!) {
  getBulkUploadJob(id: $id) {
    id
    targetJobId
    status
    total
    processed
    succeeded
    failed
    duplicates
    createdCandidateIds
    failures {
      fileName
      stage
      reason
    }
    startedAt
    completedAt
    error
    createdAt
    updatedAt
  }
}
```

## Request Parameters

<ParamField body="id" type="string" required>
  Unique identifier (UUID) of the bulk upload job, as returned by `POST /candidates/bulk-upload-resumes`. Returns `null` if no job with this ID exists in your tenant.
</ParamField>

## Response

<ResponseField name="data" type="object">
  <Expandable title="data properties">
    <ResponseField name="getBulkUploadJob" type="object">
      The bulk upload job record, or `null` if not found in your tenant.

      <Expandable title="getBulkUploadJob properties">
        <ResponseField name="id" type="string">
          Unique identifier (UUID) of the bulk upload job.
        </ResponseField>

        <ResponseField name="targetJobId" type="string">
          Identifier of the job the resumes are being uploaded to.
        </ResponseField>

        <ResponseField name="status" type="string">
          Lifecycle status of the upload. One of `PENDING`, `PROCESSING`, `COMPLETED`, `FAILED`. Poll until `COMPLETED` or `FAILED`.
        </ResponseField>

        <ResponseField name="total" type="integer">
          Total number of files in the upload.
        </ResponseField>

        <ResponseField name="processed" type="integer">
          Number of files processed so far.
        </ResponseField>

        <ResponseField name="succeeded" type="integer">
          Number of files that produced a candidate.
        </ResponseField>

        <ResponseField name="failed" type="integer">
          Number of files that failed processing.
        </ResponseField>

        <ResponseField name="duplicates" type="integer">
          Number of files skipped as duplicates.
        </ResponseField>

        <ResponseField name="createdCandidateIds" type="array">
          Identifiers of the candidate rows created by this upload.
        </ResponseField>

        <ResponseField name="failures" type="array">
          Per-file failures surfaced back to the recruiter.

          <Expandable title="BulkUploadJobFailure">
            <ResponseField name="fileName" type="string">
              Name of the file that failed.
            </ResponseField>

            <ResponseField name="stage" type="string">
              Pipeline stage where the failure occurred: `upload`, `extract`, `classify`, `score`, or `write`.
            </ResponseField>

            <ResponseField name="reason" type="string">
              Human-readable failure reason.
            </ResponseField>
          </Expandable>
        </ResponseField>

        <ResponseField name="startedAt" type="string">
          Timestamp when processing started, if it has started.
        </ResponseField>

        <ResponseField name="completedAt" type="string">
          Timestamp when processing finished, if it has finished.
        </ResponseField>

        <ResponseField name="error" type="string">
          Job-level error message when `status` is `FAILED`.
        </ResponseField>

        <ResponseField name="createdAt" type="string">
          ISO 8601 timestamp of job creation.
        </ResponseField>

        <ResponseField name="updatedAt" type="string">
          ISO 8601 timestamp of the last update.
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>
</ResponseField>
