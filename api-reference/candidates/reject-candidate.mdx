## Overview

Reject a candidate from the hiring pipeline. The mutation sets `candidateStatus` to `REJECTED` with the captured reason and emits a `CANDIDATE_REJECTED` audit event. Rejection is terminal — re-rejecting an already-rejected candidate is a no-op. Use `advanceCandidate` to move a candidate forward instead, or `deleteCandidate` to soft-delete the row entirely.

<Note>
This operation requires the **write** scope.
</Note>

## Endpoint

```
POST /graphql
Content-Type: application/json
```

## GraphQL Mutation

```graphql
mutation rejectCandidate($input: RejectCandidateInput!) {
  rejectCandidate(input: $input) {
    id
    name
    email
    jobId
    organizationId
    candidateStatus
    currentStageId
    updatedAt
  }
}
```

## Request Parameters

<ParamField body="candidateId" type="string" required>
  UUID of the candidate to reject
</ParamField>

<ParamField body="reason" type="string" required>
  Reason for the rejection, captured on the candidate and in the audit trail
</ParamField>

<ParamField body="atStageId" type="string">
  Identifier of the pipeline stage at which the candidate was rejected
</ParamField>

## Error Responses

| Error Code | Description |
| --- | --- |
| UNAUTHENTICATED | Missing or invalid API key or bearer token |
| FORBIDDEN | The token does not include the write scope |
| BAD_USER_INPUT | `candidateId` is not a valid UUID or `reason` is missing |
| NOT_FOUND | The candidate does not exist in the caller's tenant |
| INTERNAL_SERVER_ERROR | Unexpected server-side failure while rejecting the candidate |
