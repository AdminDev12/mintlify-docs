## Overview

Update a candidate's recruiter verdict — an AiVerdict slug such as `shortlisted` or `ai_screening` persisted as `verdictId` on the candidate row for grid and job-details flows. The verdict is distinct from the lifecycle `candidateStatus` (which is moved by `advanceCandidate` and `rejectCandidate`) and from the recruiter eligibility signal set by `updateCandidateEligibility`. The mutation is idempotent when the stored value already matches, and it emits a `CANDIDATE_VERDICT_CHANGED` audit event with before/after values.

<Note>
This operation requires the write scope.
</Note>

## Endpoint

```
POST /graphql
Content-Type: application/json
```

## GraphQL Mutation

```graphql
mutation UpdateCandidateVerdict($input: UpdateCandidateVerdictInput!) {
  updateCandidateVerdict(input: $input) {
    id
    name
    email
    jobId
    organizationId
    verdictId
    candidateStatus
    eligibility
    updatedAt
  }
}
```

## Request Parameters

<ParamField body="candidateId" type="string" required>
  UUID of the candidate whose verdict to update
</ParamField>

<ParamField body="verdictId" type="string" required>
  Verdict slug to persist on the candidate row (e.g. `shortlisted`, `ai_screening`)
</ParamField>

<ParamField body="reason" type="string">
  Optional free-text reason recorded alongside the change in the audit trail
</ParamField>

## Error Responses

| Error Code | Description |
|------------|-------------|
| UNAUTHENTICATED | Missing or invalid API key or bearer token |
| FORBIDDEN | The token lacks the write scope required for this mutation |
| BAD_USER_INPUT | `verdictId` is not a recognized verdict slug or `candidateId` is not a valid UUID |
| NOT_FOUND | No candidate with the given id exists in your tenant |
| INTERNAL_SERVER_ERROR | Unexpected server-side failure while persisting the change |
