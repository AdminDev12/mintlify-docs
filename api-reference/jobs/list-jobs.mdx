## Overview

The `jobs` query returns a paginated, tenant-scoped list of jobs with optional filtering by `JobStatus` and a free-text search term. Use it to power job boards, dashboards, and pickers inside your integration; the response envelope pairs the job items with a `pageInfo` block so you can drive pagination controls without a separate count query. To fetch the complete record for one job, use the `job` query instead.

## Endpoint

```
POST /graphql
Content-Type: application/json
```

## GraphQL Query

```graphql
query ListJobs($perPage: Int, $pageNumber: Int, $status: JobStatus, $search: String) {
  jobs(perPage: $perPage, pageNumber: $pageNumber, status: $status, search: $search) {
    items {
      id
      uid
      title
      category
      type
      city
      status
      department
      employmentType
      createdAt
      updatedAt
    }
    pageInfo {
      totalCount
      totalPages
      currentPage
      perPage
      hasNextPage
      hasPreviousPage
    }
  }
}
```

## Request Parameters

<ParamField body="perPage" type="integer">
  Number of jobs to return per page.
</ParamField>

<ParamField body="pageNumber" type="integer">
  Page number to retrieve (1-based).
</ParamField>

<ParamField body="status" type="JobStatus">
  Filter by job status. Allowed values: `DRAFT`, `PUBLISHED`, `CLOSED`. Omit to return jobs in every status.
</ParamField>

<ParamField body="search" type="string">
  Free-text search term used to narrow the result set.
</ParamField>

## Error Responses

| Error Code | Description |
|------------|-------------|
| UNAUTHENTICATED | Missing or invalid API key or bearer token |
| FORBIDDEN | The caller lacks read access to jobs in this tenant |
| BAD_USER_INPUT | A filter argument is malformed, such as an unknown `status` value |
| INTERNAL_SERVER_ERROR | Unexpected server-side failure |
