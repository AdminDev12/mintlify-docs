## Overview

Publish a job, setting its lifecycle status to `PUBLISHED`. Use this once a draft created with `createJob` (and enriched with `updateJob`) is ready to go live. Published jobs with `publishToCareersPage` set to true also become visible on the organization's public careers page via the unauthenticated `careersPublicJobs` query; to take a job back off the market later, use `closeJob`.

<Note>
This operation requires the `write` scope.
</Note>

## Endpoint

```
POST /graphql
Content-Type: application/json
```

## GraphQL Mutation

```graphql
mutation PublishJob($id: UUID!) {
  publishJob(id: $id) {
    id
    uid
    title
    status
    publishToCareersPage
    questionsStatus
    updatedAt
  }
}
```

## Request Parameters

<ParamField body="id" type="string" required>
  UUID of the job to publish. The job must belong to the caller's tenant.
</ParamField>

## Error Responses

| Error Code | Description |
| --- | --- |
| UNAUTHENTICATED | Missing or invalid API key or bearer token. |
| FORBIDDEN | The caller lacks the Recruiter or Admin role, or the `write` scope. |
| BAD_USER_INPUT | `id` is missing or is not a valid UUID. |
| NOT_FOUND | No job with the given `id` exists for the caller's tenant. |
| INTERNAL_SERVER_ERROR | Unexpected server-side failure while publishing the job. |
