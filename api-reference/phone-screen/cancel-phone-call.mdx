## Overview

Cancel a scheduled or in-progress phone call. The mutation flips the call's `status` to `CANCELLED`, stores the optional reason on `failureReason`, and returns the updated phone call record. It is idempotent: cancelling an already-cancelled call is a no-op that returns the existing record without a second audit emit. Use this to stop calls started with `initiatePhoneCall` or `initiateBulkPhoneCalls`.

<Note>
This operation requires the write scope.
</Note>

<Warning>
Calls in a terminal state cannot be cancelled: if the call's `status` is `COMPLETED`, `FAILED`, `NO_ANSWER`, or `BUSY`, the mutation returns `BAD_USER_INPUT`. In the current version, cancellation only updates the platform's state; an in-flight call leg is not hung up on the provider side, and its post-call webhook still fires and reconciles state.
</Warning>

## Endpoint

```
POST /graphql
Content-Type: application/json
```

## GraphQL Mutation

```graphql
mutation CancelPhoneCall($input: CancelPhoneCallInput!) {
  cancelPhoneCall(input: $input) {
    id
    candidateId
    jobId
    organizationId
    toNumber
    status
    failureReason
    updatedAt
  }
}
```

## Request Parameters

<ParamField body="phoneCallId" type="string" required>
  UUID of the phone call to cancel.
</ParamField>

<ParamField body="reason" type="string">
  Optional human-readable reason for the cancellation. Appears in the audit trail and on the record's `failureReason` field.
</ParamField>

## Error Responses

| Error Code | Description |
| --- | --- |
| `UNAUTHENTICATED` | Missing or invalid API key or bearer token. |
| `FORBIDDEN` | The caller lacks the Admin or Recruiter role, or lacks the write scope. |
| `BAD_USER_INPUT` | The call is in a terminal state (`COMPLETED`, `FAILED`, `NO_ANSWER`, or `BUSY`) and cannot be cancelled, or `phoneCallId` is not a valid UUID. |
| `NOT_FOUND` | No phone call exists for the supplied `phoneCallId` within your tenant. |
| `INTERNAL_SERVER_ERROR` | An unexpected server error occurred. |
