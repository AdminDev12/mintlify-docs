## Overview

Trigger operator-driven recovery for a phone call whose post-call ElevenLabs webhook never arrived. The mutation pulls the conversation from the provider's `/v1/convai/conversations/{id}` endpoint and replays it through the same transcription-handling path the webhook uses, so the candidate receives their transcript and analysis exactly as they would after a normal call. It is Admin-only and idempotent: re-running it on a call that is already fully reconciled returns `outcome: "already_complete"` without any writes, making it safe for cron or loop callers. Use `initiatePhoneCall` to place calls and `cancelPhoneCall` to stop them; this operation only repairs completed-but-unprocessed calls.

<Note>
This operation requires the write scope. It is additionally restricted to the Admin role and is scoped to your tenant.
</Note>

## Endpoint

```
POST /graphql
Content-Type: application/json
```

## GraphQL Mutation

```graphql
mutation ReconcilePhoneCall($input: ReconcilePhoneCallInput!) {
  reconcilePhoneCall(input: $input) {
    outcome
    conversationId
    candidateId
    phoneCallId
    transcriptSegments
    durationSeconds
  }
}
```

## Request Parameters

Provide either `conversationId` (preferred) or `candidateId`. At least one must be supplied; the resolver returns `BAD_USER_INPUT` when both are absent.

<ParamField body="conversationId" type="string">
  The ElevenLabs canonical conversation key. This is the preferred lookup key.
</ParamField>

<ParamField body="candidateId" type="string">
  Candidate identifier used as a fallback lookup: the platform resolves the candidate's latest call and uses that call's `conversationId`.
</ParamField>

## Response

  <Expandable title="data properties">
    <ResponseField name="reconcilePhoneCall" type="object">

## Error Responses

| Error Code | Description |
| --- | --- |
| `UNAUTHENTICATED` | Missing or invalid API key or bearer token. |
| `FORBIDDEN` | The caller is not an Admin, or lacks the write scope. |
| `BAD_USER_INPUT` | Both `conversationId` and `candidateId` were absent; at least one lookup key is required. |
| `INTERNAL_SERVER_ERROR` | The provider API could not be reached or an unexpected server error occurred. |

Miss states such as an unknown conversation or a missing phone call record are not GraphQL errors: they are reported via the `outcome` field (`not_found_in_provider`, `no_phone_call_record`) in a 200 response.
