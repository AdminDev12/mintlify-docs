## Overview

Re-runs the AI resume scoring pipeline for a single candidate against their job's current description. Exterview pulls the stored resume from blob storage, re-extracts the text, re-scores it, then persists the new per-section breakdown and aggregate `resumeScore`, recording a `CANDIDATE_RESUME_ANALYZED` audit event with before/after snapshots. Use it after the job description changes or a replacement resume is uploaded; for a manual score override without re-running the AI, use `updateResumeScore` instead.

<Note>
This operation requires the write scope.
</Note>

## Endpoint

```
POST /graphql
Content-Type: application/json
```

## GraphQL Mutation

```graphql
mutation analyzeResume($candidateId: UUID!) {
  analyzeResume(candidateId: $candidateId) {
    id
    name
    email
    jobId
    resumeScore
    resumeScoreDetailBreakdown
    candidateStatus
    eligibility
    skillsFound
    merits {
      title
      description
      category
    }
    updatedAt
  }
}
```

## Request Parameters

<ParamField body="candidateId" type="string" required>
  UUID of the candidate whose resume should be re-analyzed. The candidate must exist in the caller's tenant and have a resume on file, and their job must have a description.
</ParamField>

## Response

<ResponseField name="data" type="object">
  <Expandable title="data properties">
    <ResponseField name="analyzeResume" type="object">
      The updated candidate with the freshly computed score.

      <Expandable title="analyzeResume properties">
        <ResponseField name="id" type="string">
          Unique candidate identifier (UUID)
        </ResponseField>

        <ResponseField name="name" type="string">
          Candidate's full name
        </ResponseField>

        <ResponseField name="email" type="string">

        </ResponseField>

          Identifier of the job the candidate belongs to
        </ResponseField>

        <ResponseField name="resumeScore" type="number">
          Recomputed aggregate resume score
        </ResponseField>

        <ResponseField name="resumeScoreDetailBreakdown" type="object">
          Per-section score breakdown produced by the scoring pipeline
        </ResponseField>

        <ResponseField name="candidateStatus" type="string">
          Lifecycle status in the hiring pipeline. One of `APPLIED`, `IN_PROGRESS`, `ADVANCED`, `REJECTED`, `HIRED`, `WITHDRAWN`
        </ResponseField>

        <ResponseField name="eligibility" type="string">
          Recruiter's eligibility decision. One of `ELIGIBLE`, `INELIGIBLE`, `UNSET` (legacy rows without the field surface as `UNSET`)
        </ResponseField>

        <ResponseField name="skillsFound" type="array">
          Skills extracted from the resume
        </ResponseField>

        <ResponseField name="merits" type="array">
          Job-description-relevant strength cards composed at extraction time

          <Expandable title="Merit Object">
            <ResponseField name="title" type="string">
              Strength card title
            </ResponseField>

            <ResponseField name="description" type="string">
              Strength card description
            </ResponseField>

            <ResponseField name="category" type="string">
              Strength category, for example skill, domain, or certification (nullable)
            </ResponseField>
          </Expandable>
        </ResponseField>

        <ResponseField name="updatedAt" type="string">
          ISO 8601 timestamp of the last update
        </ResponseField>
      </Expandable>
    </ResponseField>
  </Expandable>

## Error Responses

| Error Code | Description |
| --- | --- |
| UNAUTHENTICATED | Missing or invalid API key or bearer token |
| FORBIDDEN | The caller lacks the write scope for this tenant |
| BAD_USER_INPUT | The candidate has no resume on file, or the job has no description |
| NOT_FOUND | The candidate id does not exist in the caller's tenant |
| INTERNAL_SERVER_ERROR | Blob fetch failed, the AI scorer threw, or the write failed |
