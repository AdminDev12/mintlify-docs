## Overview

Manually overrides a candidate's per-section resume score breakdown. Each section's score is validated as an integer from 0 to 100, and the server recomputes the aggregate `resumeScore` from the breakdown using the default weights so the headline number never desyncs from the per-section detail. The change is captured in the audit log as `CANDIDATE_SCORE_OVERRIDDEN` with before/after snapshots, and the call is idempotent: an update that produces the same breakdown bytes is a no-op. To re-run the AI scoring pipeline instead of overriding by hand, use `analyzeResume`.

<Note>
This operation requires the write scope.
</Note>

## Endpoint

```
POST /graphql
Content-Type: application/json
```

## GraphQL Mutation

```graphql
mutation updateResumeScore($input: UpdateResumeScoreInput!) {
  updateResumeScore(input: $input) {
    id
    name
    jobId
    resumeScore
    resumeScoreDetailBreakdown
    updatedAt
  }
}
```

## Request Parameters

<ParamField body="candidateId" type="string" required>
  UUID of the candidate whose score breakdown is being overridden.
</ParamField>

<ParamField body="resumeScoreDetailBreakdown" type="object" required>
  The full per-section score breakdown. Each section's score must be an integer from 0 to 100; the server recomputes the aggregate `resumeScore` from this breakdown using the default weights.
</ParamField>

<ParamField body="reason" type="string">
  Optional reason for the override, captured in the audit log.
</ParamField>

## Error Responses

| Error Code | Description |
| --- | --- |
| UNAUTHENTICATED | Missing or invalid API key or bearer token |
| FORBIDDEN | The caller lacks the write scope for this tenant |
| BAD_USER_INPUT | A section score is missing, not an integer, or outside 0 to 100 |
| NOT_FOUND | The candidate id does not exist in the caller's tenant |
| INTERNAL_SERVER_ERROR | Unexpected server error while persisting the override |
