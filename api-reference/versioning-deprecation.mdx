## Who this is for

Developers and enterprise buyers evaluating API stability and long-term integration safety.

## Additive-only guarantee

The Exterview GraphQL API follows an **additive-only** versioning model:

- New fields, types, and operations are added without removing or changing existing ones
- Existing client integrations continue to work without modification
- Breaking changes require advance notice and a documented deprecation timeline

This policy is a trust feature enterprise integrations can rely on API stability.

## Deprecation process

When a field or operation must be deprecated:

1. **Announcement** Deprecated items are marked in the API schema and documented in the [Changelog](/faq-changelog/changelog)
2. **Notice period** Minimum notice period before removal (timeline to be confirmed per deprecation)
3. **Migration guide** Documentation provides the replacement operation or field
4. **Removal** Only after the notice period expires and usage metrics confirm migration

## Versioning

The API uses a single endpoint with schema-level versioning. There are no versioned URL paths (e.g., `/v1/`, `/v2/`). Schema changes are additive and backward-compatible.
